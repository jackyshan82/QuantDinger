# Orca 多 agent 研究分工方案

[English](RESEARCH_TEAM.md) · [共享研究 skill](../../.agents/skills/quantdinger-research/SKILL.md)

采用一个协调者和三个角色。项目 skill 定义研究流程与交付物，Orca 的
`orchestration` skill 负责真正启动、登记、监督和回收 worker。

| 角色 | 负责什么 | 必须交付什么 |
| --- | --- | --- |
| 股票池与因子研究员 | 按过去数据确定候选范围，再检查因子、稳定性和成本 | 名单与原生股票池 ID、因子报告、研究编号和排除证据 |
| 策略研发员 | 编写 V2 策略、声明参数范围、运行原生策略进化 | 冻结后的源码版本/指纹、有效参数、进化任务编号 |
| 独立验证员 | 预先制定验收方案，核查源码与成交，运行独立回测 | 逐项通过/淘汰/证据不足结论、回测编号 |
| 协调者 | 固定研究计划、安排依赖、控制预算、核查结果与 Orca 生命周期 | 计划、任务记录、最终报告和交接更新 |

## 实际怎么跑

1. **先固定研究约定。** 明确标的、周期、只做多或多空、是否允许隔夜、数据区间、
   手续费和滑点、有限参数预算，以及盈利、回撤、交易样本等验收条件。
   已明确的选择直接沿用；只补充影响结果的缺失信息。
2. **第一批并行准备。** 股票池与因子研究员先提交[候选名单](../trading/RESEARCH_UNIVERSE_CN.md)，
   协调者确认后才运行原生因子研究；研发员准备策略框架和参数方案；
   验证员提前写验收标准，暂不查看最终测试结果。这一批只由因子研究员提交重型原生任务。
3. **按依赖完成研发。** 协调者接受因子证据和验收方案后，再让研发员实现假设、
   编译和运行原生策略进化，搜索仅限开发区间。交付源码 ID、版本、指纹、清单和有效参数，冻结候选。
4. **独立验证。** 验证员核对冻结包，运行原生外部回测、基准比较和成本压力测试，
   检查未来数据、下一根成交、日内平仓、缺失或延迟成交。不能边验收边改参数。
5. **协调者收尾。** 汇总通过、淘汰或证据不足，链接所有原生记录，处理 worker 完成消息、
   回收或按规则复用资源，更新交接。研究通过不意味着可以启动实盘。

三个角色不必一直占着三个进程。某个 Task 结束后，有立即可做的后续任务才复用同一 worker；
否则按 Orca 指南回收，后续阶段再为同一角色启动新的 worker。

## 怎样避免互相干扰

- 每轮在 `artifacts/` 下创建新的带日期研究目录，各角色分别拥有 `factor/`、
  `strategy/`、`validation/`，不会同时改同一个文件。
- 研发员拥有候选源码；验证员只读源码并拥有验收报告。修复技术问题必须通过新 Task
  退回研发员，产生新版本、指纹和验证记录。
- 原生因子研究、进化、回测按阶段提交，先限制为同一时间一个重型研究任务。
  多 agent 的并行主要用于不同分析和准备工作，避免同时挤占行情接口、数据库连接和 CPU。
- 分别记录 Orca Run/Task/Dispatch ID 与 QuantDinger 研究/任务/回测 ID。
  超时后先查现有回执，不重复提交任务或重复启动 worker。
- 验证员在最终结果出现前写标准，不参与参数选择；看过的测试区间不能重新称为未知盲测。
  共用目录和数据库属于协作边界，不是能够隐藏测试数据的强制安全隔离。
- 策略不赚钱可以是本轮正确的研究结论；worker 执行成功和策略通过验收是两个状态。

具体任务模板和角色指令见 skill 的
[团队流程](../../.agents/skills/quantdinger-research/references/team-workflow.md)。
每次启动前读取当前 Orca CLI 提供的版本匹配指南，以实际返回的登记和生命周期回执为准。

## 下次如何调用

可以这样发任务：

> 使用 quantdinger-research 和 Orca orchestration，按因子研究、策略研发、独立验证
> 三个角色研究 NVDA 日内策略。先冻结研究计划，再使用项目原生功能执行，保留失败候选，
> 汇总原生记录。不要启动实盘。

本文件和角色模板只是可复用配置，本身没有启动 worker，也不代表已经找到盈利策略。
