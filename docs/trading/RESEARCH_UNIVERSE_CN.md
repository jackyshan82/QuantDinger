# 研究股票池的准备与筛选

[English](RESEARCH_UNIVERSE.md)

后端新增了研究用筛选服务和命令行入口，复用原生股票池、当前用户的历史行情连接、
股票池快照和私有手工股票池保存功能。它负责在因子研究前确定候选范围，不根据未来
策略收益挑股票，不启动进化或交易，也没有增加前端筛选页面。

## 输入与输出

先固定母池（例如纳指 100）、已结束的筛选截止日、更晚的研究起点、回看区间、周期和过滤条件。
服务按截止日解析母池成员，只处理截止日以前已完成的 K 线，转换纽约时间并保留正常交易时段。

支持按已观测交易日数量、每交易日 K 线数量中位数、最近价格、每交易日成交额代理值中位数、
数据陈旧天数过滤。可限制候选数量，按历史成交额代理值排序，同值按代码排序，不看策略收益。
价格和成交额下限默认 0，表示未启用；示例中的数字是研究配置，不是通用流动性或风险标准。

输出 JSON 记录全部母池成员、入选和排除原因、指标、行情来源、数据指纹、母池成员指纹、
日期、过滤策略、候选名单与整体筛选指纹。只有完整扫描且候选数量足够，状态才是 `ready`。
行情请求失败时为 `incomplete`；完整扫描后候选不足时为 `insufficient_candidates`。

## 如何调用

在 `backend_api_python` 中执行。先核对当前用户和可见股票池，不能把示例编号当作任意账户授权。
可用 `python scripts/prepare_research_universe.py --help` 查看全部参数。

先仅解析母池，不拉行情、不写数据库：

```bash
python scripts/prepare_research_universe.py \
  --user-id USER_ID --universe-id POOL_ID \
  --as-of 2025-08-29 --research-start 2025-09-01 \
  --plan-only --output /tmp/new-study/universe/plan.json
```

再按事先约定的条件筛选。例如回看 60 个自然日的 15 分钟数据，至少 20 个已观测交易日、
每交易日 K 线数中位数至少 20，并以最多 20 只控制后续研究资源：

```bash
python scripts/prepare_research_universe.py \
  --user-id USER_ID --universe-id POOL_ID \
  --as-of 2025-08-29 --research-start 2025-09-01 \
  --frequency 15m --lookback-days 60 \
  --min-sessions 20 --min-session-bars 20 --max-candidates 20 \
  --output /tmp/new-study/universe/selection.json
```

示例日期在本工作区已被研究过，不是全新盲测区间。按本轮计划替换日期和编号。
默认只读；完整扫描命令加 `--save-name NAME` 才会通过原生服务保存私有股票池。
保存前会核对整体指纹、用户和母池快照；同一完整结果可复用已有股票池，已被改动的名单会拒绝复用。
已存在的输出文件不会被覆盖。

已经生成 JSON 时，也可直接调用
`ResearchUniverseService.persist(user_id=..., report=..., name=...)`，不必重新拉取行情。
该路径使用同样的完整性和权限校验。本次没有新增数据库表或 HTTP 接口。

## 如何理解结果

- 筛选结果是从研究起点开始使用的固定候选池，不是动态调仓引擎。
  `not_valid_before` 元数据记录了使用边界，其他应用接口尚未全局强制检查这个字段。
- 明知来自当前成分回填的股票池，不能用于快照日期以前的选池。
  手工池会注明固定名单性质；当前自选列表和标的主表不能提供历史成员选择。
- 按日期解析不等于已经独立验证了所有历史指数成分，仍要核查母池来源和覆盖情况。
- 交易日/K 线数量只基于已返回数据，没有完整交易所日历校验，不能据此证明没有整日缺失、
  节假日或提前收盘差异。
- 成交额代理值为配置行情源上 `close × volume` 的日内求和；IEX 不代表全市场成交额。
  复权历史还可能反映后来公司行动，限制未来 K 线时间戳不等于所有价格信息都严格按历史时点还原。
- 全池扫描会产生多次行情请求，先限制同时只有一个重型研究任务。
  数据失败应保留原因，不能偷偷只选请求成功的股票。

股票池与因子研究员先交付名单、指纹和原生池 ID；协调者确认范围后再运行因子研究，
独立验证员在验收冻结策略时核查选池日期和名单。详见[多 agent 分工](../agent/RESEARCH_TEAM_CN.md)。
